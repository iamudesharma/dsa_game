# Web frontend end-to-end validation — 2026-10-08

The final production frontend is running at **http://localhost:3000**, against
http://127.0.0.1:8787. The existing API was preserved. Browser journeys used
headless Chromium with disposable `@example.test` accounts, desktop 1440×1000
and mobile 390×844 viewports.

## Findings fixed

1. **Transient session validation logged the user out.** `AuthProvider` now
   preserves the saved token unless the server returns HTTP 401. Connection
   failures offer an explicit retry; successful retry restores the profile.
2. **Provider deadlines exceeded the client deadlines.** Interview generation
   previously stopped at 120 seconds and coach requests at 60 seconds, while
   their configured provider could take 180 seconds. Both now use the existing
   configurable `NEXT_PUBLIC_GENERATE_TIMEOUT_MS` budget (240 seconds by
   default), with no automatic mutation retries.
3. **Reopening a saved interview kit crashed.** Stored kit responses omit
   generation diagnostics. `getInterviewKit` supplies an empty `notes` array,
   keeping the view contract consistent with newly generated kits. A transport
   regression test covers the actual saved-response shape.

A Next.js development-cache failure also occurred after hot reloads. The stale
cache was moved out of the checkout and the frontend was rebuilt. Final browser
checks used the production server, which remains running.

## Repeatable harnesses

With the frontend and API running, from the repository root:

```sh
node scripts/web-e2e.cjs
node scripts/web-extra-e2e.cjs
node scripts/web-catalogue-e2e.cjs
node scripts/web-session-recovery-e2e.cjs
node scripts/web-controls-e2e.cjs
DSA_EFFECT_WEB_URL=http://localhost:3000 node scripts/effect-browser-smoke.cjs
```

The main suite writes `/tmp/dsa-web-e2e/session.json` for the control suite.
`DSA_WEB_URL` and `DSA_E2E_OUTPUT` configure the main/supplemental harnesses;
`DSA_API_URL` configures catalogue retrieval, and `DSA_E2E_SESSION_FILE` can point
controls at another main-suite session. PDF/DOCX extraction fixtures are in
`scripts/fixtures/web-e2e`. Results and screenshots from this run are in
`/tmp/dsa-web-e2e`; session-state files contain disposable test credentials.

## Coverage limits

All missions were opened in the browser; full action-by-action completion was
exercised for array maximum/minimum, supported by the separate all-oracle
playability tests. This does not prove every UI mechanic on every seed.
Browser testing covered Chromium, not Firefox or Safari. It does not exhaust
all alternative provider responses, interview regeneration/new-angle variants,
all malformed uploads, accessibility, security or sustained load. Scanned PDFs
were not tested. Production was checked after the fixes; the entire initial
sweep was not repeated on production.

Existing unrelated Flutter/UI parity and Rust changes were preserved. Nothing
was committed or published as part of this validation.
